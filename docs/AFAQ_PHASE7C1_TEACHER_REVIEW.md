## ما تغير ولماذا

كانت المساحة تعرض قائمة بمهارات إنجليزية ومعلومات مختصرة ومفتاحًا لبعض الأنشطة فقط، وتسمح بالاعتماد والرفض دون حالة تصحيح أو عدادات أو استرجاع واضح للتعليقات. أصبحت تعرض:

- الأنشطة الـ22 كلها حسب صفحة الدرس الرسمية 220 ←223 ←224 ←225 ←226، مع ترتيب الإنشاء الأصلي داخل الصفحة نفسها. هذه قائمة مراجعة، ولا تدعي أن الأنشطة المواءمة من AFAQ أسئلة كتاب منقولة حرفيًا. لم تُرتب مصفوفة المنهج أو مسار الطالب من جديد.
- قائمة مرقمة تظهر حالة كل نشاط، وشبكة تنقل مباشرة، وزري السابق والتالي، وملخص أعداد المعتمد ويحتاج تعديلًا والمرفوض وقيد المراجعة.
- السؤال والهدف والاختيارات أو بطاقات البحث أو قطع التركيب، والإجابة الصحيحة أو جميع مواضع البحث أو المعيار البشري للقراءة والخط. الإثراء غير المقوم معلن كما هو.
- المهارة باسم عربي، والمتطلبات، وصفحة PDF واسم المصدر، والتحذيرات الموجودة عن التنوين والهمزة والاتصال والكلمة المتدرَّب عليها.
- اسم المراجع وتعليق محدد وطلبات التصحيح، مع ثلاث قرارات صريحة: معتمد، يحتاج تعديلًا، مرفوض. التعليق والاسم مطلوبان، وجميع فحوص الجودة السبعة مطلوبة للاعتماد. لا اعتماد تلقائي أو تعديل للسؤال.
- التعليقات والقرارات المحفوظة تُسترجع من السجل. المسودة غير المحفوظة تبقى أثناء التنقل ومعاينة الطالب في الجلسة الحالية فقط؛ لإبقائها بعد إعادة التحميل اضغط أحد قرارات الحفظ. تظهر آخر مراجعة مطابقة لبصمة المحتوى الحالية.
- معاينة الطالب تستخدم المشغل والسبورة والصوت الحاليين دون تسجيل استجابة أو نتيجة. يمكن العودة إلى نفس النشاط وتعليقه. لا يمكن دخول معاينة المعلم مباشرة من وضع الطالب؛ مسار الطالب الحقيقي يظل مشروطًا بالموافقة والمتطلبات والإتاحة.

تستخدم عناصر الواجهة Tajawal، والنصوص التعليمية والاختيارات Noto Naskh Arabic مع مساحة للحركات. توجد حالات RTL وهاتف/لوحي/كمبيوتر ووضعان فاتح وداكن. لم يتغير الشعار أو محرك الصوت، ولم نوسع نطاق معالجة Hoda في هذه المهمة.

## التخزين والبوابات

أُعيد استخدام `afaq-unit3-alif-pilot-v1` وأحداث `kind:quality` الموجودة، منفصلة النوع عن response/submission/observation وعن التشخيص والإتقان القديم. أضيفت قيمة `needs-revision` إلى قرارات الجودة فقط، دون تغيير إصدار التخزين أو إعادة كتابة أحداث سابقة. المراجعات، كما في الطيار السابق، تخص الطالب المحلي المحدد؛ ليست اعتمادًا عامًا لكل الملفات.

يُحفظ كل قرار جديد مع بصمة البند الحالية والمراجع والتعليق. الاعتماد هو آخر قرار جودة مطابق للبصمة فقط؛ «يحتاج تعديلًا» و«مرفوض» يمنعان الإتاحة الحالية. عند تغير المحتوى يعود إلى قيد المراجعة ولا يكفي اعتماد البصمة السابقة، مع بقاء السجل القديم. لا تغيير للإتقان أو محاولات الطالب التاريخية بسبب قرار جودة.

تبديل المعلم محلي وليس مصادقة أو تفويضًا أمنيًا؛ قيود واجهة الطفل لا تمثل حماية من مستخدم قادر على تعديل شيفرة المتصفح أو localStorage. لا خدمة خارجية ولا تسجيل دخول جديد.

## فتح شاشة المراجعة محليًا

1. افتح عنوان التطبيق المحلي المعتاد في Chrome، بنفس المتصفح والعنوان والمنفذ المستخدمين لبياناتك الحالية. التخزين مرتبط بالأصل؛ فتح منفذ مختلف لا ينقل البيانات إليه ولا يعني حذفها.
2. إذا لم يكن خادم التطبيق يعمل، افتح PowerShell في المشروع وشغل:

   ```powershell
   Set-Location 'C:\Users\Saif Ahmed\Desktop\Seviat-Academy-App'
   python -m http.server 8000 --bind 127.0.0.1
   ```

   ثم افتح `http://127.0.0.1:8000/`. لا تفتح index عبر file://. إن كان منفذك المعتاد مختلفًا فاستخدمه بدل 8000.
3. اضغط زر القائمة ☰، ثم «المعلم وولي الأمر».
4. اختر ملف الطالب المقصود من «طلابي» عند الحاجة، ثم «إعدادات متقدمة».
5. افتح «مراجعة أنشطة حرف أ — 22 نشاطًا».
6. اختر النشاط من القائمة أو الشبكة، واقرأ السؤال والاختيارات والمفتاح والمعيار والمصدر. اضغط «معاينة الطالب — دون حفظ» لتجربة واجهة الطالب ثم «العودة للمعلم».
7. اكتب اسمك وتعليقًا محددًا. للاعتماد، راجع وأكد فحوص الجودة السبعة ثم اضغط «اعتماد البند». وإلا اختر «يحتاج تعديلًا» مع التصحيح المطلوب أو «رفض البند» مع السبب.
8. راقب العداد وحالة النشاط ثم انتقل للتالي. أعد التحميل للتحقق من القرار المحفوظ. عرض النشاط أو معاينته لا يعتمده ولا يتيح تجربة الطالب تلقائيًا.

إتاحة الطيار والتحقق من مهارات فَأْسٌ والملاحظات البشرية للقراءة والخط تبقى في المساحة نفسها دون تغيير قواعدها. هذه المهمة لا تتطلب إتاحة الطيار لمجرد مراجعة المحتوى.
